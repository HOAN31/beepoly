## Entity: bo_the_tu_vung (Deck)

Represents a vocabulary deck. Maps to table `bo_the_tu_vung` in `beepoly.sql`.

| Field | SQL Column | Type (DB) | Type (prototype) | Required | Description |
|---|---|---|---|---|---|
| id | id | BIGINT PK (auto-increment) | `string` | yes | Primary key. In the prototype mock it is a string key (e.g. `"deck-eng-vocab"`); in the DB it is a BIGINT PK (spec §14.1 uses `id: string`). |
| userId | nguoi_dung_id | BIGINT | `string` | yes | Owner of the deck |
| title | tieu_de | VARCHAR(200) | `string \| null` | no | Deck title |
| sourcePdfUrl | source_pdf_url | VARCHAR(500) | `string \| null` | no | PDF source if imported |
| isAutoGenerated | is_auto_generated | BOOLEAN | `boolean` | yes | True if created by PDF import, default false |
| createdAt | ngay_tao | TIMESTAMPTZ | `string` (ISO) | yes | Creation date, default `now()` |

**This table has NO description, category, difficulty, or last-studied column.** See §Fields removed below.

---

## Fields removed — no SQL column

These were requested in earlier design notes but have **no column** in `beepoly.sql` and cannot be derived from any existing column. They are **not** shown on Deck List, and nothing in the DB is invented to support them.

| Field | Why removed | What would be required |
|---|---|---|
| `description` | `bo_the_tu_vung` has no description column | New column, e.g. `mo_ta TEXT` |
| `category` | No category column | New column + lookup table |
| `difficulty` badge | No difficulty column | New column or enum |
| last-studied time | No last-studied column. `lich_su_on_the.lan_on_tiep_theo` is the **NEXT** review time, not a last-studied timestamp — it must not be presented as one. | New column, e.g. `ngay_on_gan_nhat TIMESTAMPTZ` |
| Category filter dropdown | Depends on the removed `category` field | Unlocks automatically once a category column exists |

**In place of the removed metadata**, the deck card shows `ngay_tao` as `Created` — the only timestamp column `bo_the_tu_vung` actually has.

## Cover icon (presentation-only)

The cover icon on each Deck Card is **not a stored field**. `bo_the_tu_vung` has no icon or category column, and nothing is invented in the DB to support it.

- Chosen **deterministically from the deck `id`** — the same deck always renders the same icon and tone.
- Pure UI decision (Lucide icon + tinted tile). No schema misrepresentation; no mock column.

## Derived values shown on Deck Card

All derived values are computed client-side from mock review-log data using the **same rule** the full MVP will use against `lich_su_on_the`. Swapping mocks for Supabase queries later does not change the UI.

| Value | Definition | SQL source |
|---|---|---|
| `cardCount` | Count of `the_tu_vung` where `bo_the_id` = deck.id | `the_tu_vung` |
| `mastery` | `(mastered cards / total cards) × 100`, rounded. `0` when `cardCount === 0`. | `lich_su_on_the.khoang_cach_ngay` |
| `hasDueCards` | ≥ 1 card with status `New`, **or** status `Learning` and `lan_on_tiep_theo <= now()` | `lich_su_on_the` |
| `isFullyMastered` | `cardCount > 0` and **every** card has status `Mastered` | `lich_su_on_the.khoang_cach_ngay` |

> **Naming note.** Earlier drafts of this file called the mastery value `masteryPercent`. The spec and TypeScript types name it **`mastery`** (0–100). Use `mastery` everywhere.

## Card Status Derivation

Card status is **not stored** in the database. It is derived from `lich_su_on_the`:

| Status | Condition |
|---|---|
| `New` | No row in `lich_su_on_the` for `(nguoi_dung_id, flashcard_id)` |
| `Learning` | Row exists AND `khoang_cach_ngay <= 21` |
| `Mastered` | Row exists AND `khoang_cach_ngay > 21` |

## Filter Values

| Value | Label | Condition |
|---|---|---|
| `all` | All | Show all decks for the current user. **Default.** |
| `due` | Due for review | Deck has ≥ 1 card with status `New`, **or** status `Learning` and `lan_on_tiep_theo <= now()` (i.e. `deck.hasDueCards`) |
| `mastered` | Mastered | Deck has 0 cards with status `New` or `Learning` — every card is mastered (i.e. `deck.isFullyMastered`) |

**Notes.**

- **`mastered` requires 100% mastery**, not "majority mastered". A deck at 75% does **not** appear under `Mastered`.
- In the prototype the filter is applied **client-side** via `applyDeckFilters` (spec §14.3), combining status filter and title search with **AND**. Default selection on mount is `all`.

## Related types

Three schema-mirroring types plus one derived type. No extra fields beyond the columns below.

| Type | Mirrors | Key fields |
|---|---|---|
| `Deck` | `bo_the_tu_vung` | `id`, `userId`, `title`, `sourcePdfUrl`, `isAutoGenerated`, `createdAt` |
| `Flashcard` | `the_tu_vung` | `id`, `deckId`, `word`, `meaning`, `example`, `audioUrl` |
| `ReviewLog` | `lich_su_on_the` | `userId`, `cardId`, `easeFactor`, `intervalDays`, `nextReviewAt`, `wrongCount` |
| `DeckWithStats` | `Deck` + derived | adds `cardCount`, `mastery` (0–100), `hasDueCards`, `isFullyMastered` |

**DB constraints** (enforced in `beepoly.sql`, noted here for consistency — **not** visible UI fields):

- `check_the_tu_vung_tu_khong_trang`: `tu` (word) must be non-empty after trimming — whitespace-only input is rejected, not just null.
- `uq_the_tu_vung_bo_the_tu`: a word may appear only **once per deck** (unique on `(bo_the_id, tu)`). Does not affect Deck List itself (which never writes cards).
- `he_so_do_de` (easeFactor): must be **1.30–3.00**.
- `khoang_cach_ngay` (intervalDays): must be **>= 0**.
- `so_lan_sai` (wrongCount): must be **>= 0**.

## Data storage

| Mode | How data is stored / read |
|---|---|
| **Prototype (current)** | Mock rows shaped **exactly** like `beepoly.sql`. No backend, no API, no authentication, no real review logic. No invented columns. State resets on reload. |
| **Full MVP (later)** | PostgreSQL via **Supabase**, reading/writing against tables `bo_the_tu_vung`, `the_tu_vung`, `lich_su_on_the`. |

Related tables in the DB:

- `bo_the_tu_vung` — decks
- `the_tu_vung` — flashcards (FK `bo_the_id` → `bo_the_tu_vung.id`)
- `lich_su_on_the` — review logs (composite PK `(nguoi_dung_id, flashcard_id)`)
