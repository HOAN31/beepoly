# Implementation Plan

## Tech Stack

- React + TypeScript
- Vite
- Tailwind CSS
- shadcn/ui components
- Lucide icons
- React Router

No Supabase, no backend, no API, no auth. Mock data only.

## Route

| Route | Screen |
|---|---|
| `/decks` | Deck List (prior screen, xem specs/deck-list/) |
| `/decks/:deckId` | Deck Detail |
| `/decks/:deckId/review` | Review Session — placeholder only |

## Components

From `deck-detail-screen-specification.md` §11:

1. **DeckDetail** (page) — layout, state, orchestration
2. **DeckHeader** — title, created date, Edit / Delete / + Add card / Start Review
3. **StatisticCard** — one statistics tile
4. **FlashcardTable** — flashcard list (desktop table / mobile card list)
5. **StatusBadge** — New / Learning / Mastered pill
6. **SearchBar** — client-side list filter
7. **EmptyState** — no cards / no search results
8. **LoadingSkeleton** — header, stats row, and table skeleton
9. **ConfirmDialog** — delete confirmation
10. **EditDeckDialog** — edit `tieu_de` only
11. **FlashcardDetailDialog** — View card detail
12. **ReviewSession** (page) — placeholder only

### Shared conventions

- All components accept `className` and forward it to the root element.
- No component fetches data directly — pages pass props.
- Empty / loading states are components, not inline conditionals.
- Icons from **Lucide** only.
- Design: white background, blue primary (`#2563eb`-class), `rounded-xl`, 8px spacing rhythm; transitions ≤150ms, opacity/transform only.

## State Design

```ts
/** Mirrors bo_the_tu_vung. No extra fields. */
interface Deck {
  id: string;
  userId: string;
  title: string | null;          // nullable → "Untitled deck"
  sourcePdfUrl: string | null;
  isAutoGenerated: boolean;
  createdAt: string;             // ISO
}

/** Mirrors the_tu_vung. No extra fields. */
interface Flashcard {
  id: string;
  deckId: string;
  word: string;                  // tu — NOT NULL, non-blank
  meaning: string | null;        // nghia
  example: string | null;        // vi_du
  audioUrl: string | null;       // duong_dan_am_thanh
}

/** Mirrors lich_su_on_the. Composite PK: (userId, cardId). */
interface ReviewLog {
  userId: string;
  cardId: string;
  easeFactor: number;            // 1.30–3.00
  intervalDays: number;          // >= 0
  nextReviewAt: string | null;
  wrongCount: number;            // >= 0
}

type CardStatus = "New" | "Learning" | "Mastered";

type DeckStatistics = {
  total: number;
  mastered: number;
  learning: number;
  newCount: number;
  accuracy: number;              // 0–100
  estimatedLearningTime: string; // "~40 min"
};
```

Page-level state:

- `deck: Deck`
- `cards: Flashcard[]`
- `logs: ReviewLog[]`
- `stats: DeckStatistics` — derived via `deriveStats`
- `search: string`
- `page: number`
- dialog open flags: `editOpen`, `deleteOpen`, `viewCardId`

Status is **not** stored on the card object. Derive client-side from `logs` with the same rule the MVP will use in SQL.

## Data Flow

1. Load mock `deck`, `cards`, `logs` (shaped exactly like `beepoly.sql`).
2. Derive each card's status: `deriveStatus(logByCard.get(card.id))`.
3. Compute statistics: `deriveStats(cards, logs)` — invariant `mastered + learning + newCount === total`.
4. Filter by search (`tu` or `nghia`), then paginate (10/page desktop, 5/page mobile).
5. FlashcardTable renders Question / Answer preview / Status / Action.
6. View card → FlashcardDetailDialog (example & audio hidden when null).
7. Edit → EditDeckDialog updates local `deck.title`; Delete → ConfirmDialog then navigate to Deck List.
8. Start Review → navigate to Review Session placeholder.

## Testing Approach

- Manual testing against `specs/deck-detail/acceptance-criteria.md` (prototype checklist = §14.1 of the screen spec).
- Verify mock data satisfies `Mastered + Learning + New = Total` and Accuracy = `0%` when no review history.
- No automated tests required for this prototype.
