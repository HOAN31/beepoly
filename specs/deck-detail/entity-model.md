# Entity Model

Prototype uses mock rows shaped exactly like `beepoly.sql`. No invented columns. Types below mirror the schema (see `deck-detail-screen-specification.md` §12).

## Entity: bo_the_tu_vung (Deck)

Represents a vocabulary deck. Maps to table `bo_the_tu_vung` in beepoly.sql.

| Field | SQL Column | Type | Required | Description |
|---|---|---|---|---|
| id | id | BIGINT | yes | Primary key, auto-increment |
| userId | nguoi_dung_id | BIGINT | yes | Owner of the deck |
| title | tieu_de | VARCHAR(200) | no | Deck title — nullable; render `Untitled deck` when null |
| sourcePdfUrl | source_pdf_url | TEXT | no | PDF source if imported |
| isAutoGenerated | is_auto_generated | BOOLEAN | yes | True if created by PDF import, default false |
| createdAt | ngay_tao | TIMESTAMPTZ | yes | Creation date, default now() |

Note: This table has NO description, category, or difficulty field. Those were removed from the screen — no SQL column exists.

## Entity: the_tu_vung (Card / Flashcard)

Represents a single vocabulary flashcard inside a deck. Maps to table `the_tu_vung` in beepoly.sql.

| Field | SQL Column | Type | Required | Description |
|---|---|---|---|---|
| id | id | BIGINT | yes | Primary key, auto-increment |
| deckId | bo_the_id | BIGINT | yes | Parent deck reference |
| word | tu | VARCHAR(150) | yes | English word — non-empty after trim (`check_the_tu_vung_tu_khong_trang`); unique per deck (`uq_the_tu_vung_bo_the_tu`) |
| meaning | nghia | TEXT | no | Vietnamese meaning |
| example | vi_du | TEXT | no | Example sentence |
| audioUrl | duong_dan_am_thanh | TEXT | no | Pronunciation audio URL |

Note: This table has NO status column — status is derived (see below).

## Entity: lich_su_on_the (ReviewLog)

Tracks spaced repetition data per card per user. Maps to table `lich_su_on_the` in beepoly.sql.

| Field | SQL Column | Type | Required | Description |
|---|---|---|---|---|
| userId | nguoi_dung_id | BIGINT | yes | The learner (part of composite PK) |
| cardId | flashcard_id | BIGINT | yes | The flashcard (part of composite PK) |
| easeFactor | he_so_do_de | NUMERIC(3,2) | yes | SM-2 ease factor, default 2.5; must be 1.30–3.00 |
| intervalDays | khoang_cach_ngay | INTEGER | yes | Days until next review, default 1; must be >= 0 |
| nextReviewAt | lan_on_tiep_theo | TIMESTAMPTZ | no | Scheduled next review date |
| wrongCount | so_lan_sai | INTEGER | yes | Times rated "Again", default 0; must be >= 0 |

Primary Key: (nguoi_dung_id, flashcard_id)

## Card Status Derivation

Card status is NOT stored in the database. It is derived from `lich_su_on_the` using the same rule client-side in the prototype:

| Status | Condition |
|---|---|
| New | No row in `lich_su_on_the` for `(nguoi_dung_id, flashcard_id)` |
| Learning | Row exists AND `khoang_cach_ngay <= 21` |
| Mastered | Row exists AND `khoang_cach_ngay > 21` |

Canonical labels are title case: `New` / `Learning` / `Mastered`.

```ts
function deriveStatus(log: ReviewLog | undefined): CardStatus {
  if (!log) return "New";
  return log.intervalDays > 21 ? "Mastered" : "Learning";
}
```

## Deck Statistics (derived)

| Statistic | Label | How calculated | Badge tone |
|---|---|---|---|
| total | `Total` | Count of `the_tu_vung` where `bo_the_id` = deck.id | Neutral |
| mastered | `Mastered` | Cards with status `Mastered` (`khoang_cach_ngay > 21`) | Success (green) |
| learning | `Learning` | Cards with status `Learning` (`khoang_cach_ngay <= 21`) | Warning (amber) |
| new | `New` | Cards with status `New` (no `lich_su_on_the` row) | Info (blue) |
| accuracy | `Accuracy` | (cards with `so_lan_sai = 0` / cards with review history) × 100%; `0%` if no review history | Primary (blue) |
| estimatedLearningTime | `Est. learning time` | `Total × 20 seconds`, formatted e.g. `~40 min` / `~1 h 20 min` | Caption under the stats row |

Invariant: Mastered + Learning + New = Total. Mock data must satisfy this.

> Naming note: `skill.md` calls these `Completed` and `Need Review`. Those map to `Mastered` and `Learning`. Use the labels above.

## Prototype Mock Data

Only schema columns. Deck id and title from `skill.md`; statistics satisfy the invariant above.

```ts
const deck: Deck = {
  id: "deck-eng-vocab",
  userId: "user-1",
  title: "English Vocabulary",
  sourcePdfUrl: null,
  isAutoGenerated: false,
  createdAt: "2026-03-14T09:00:00.000Z",
};

const statistics: DeckStatistics = {
  total: 120,
  mastered: 62,
  learning: 28,
  newCount: 30,       // 62 + 28 + 30 === 120
  accuracy: 82,
  estimatedLearningTime: "40 min",
};
```

Sample review logs — chosen to produce all three statuses:

| Card | `intervalDays` | Derived status |
|---|---|---|
| `c1` | 7 | `Learning` |
| `c2` | *(no row)* | `New` |
| `c3` | 45 | `Mastered` |
| `c4` | 14 | `Learning` |
| `c5` | 30 | `Mastered` |

## Data Storage

- Prototype: mock rows in memory only — no backend, no API, no network calls; state resets on reload
- Future full MVP: PostgreSQL (Supabase)
- Tables: `bo_the_tu_vung`, `the_tu_vung`, `lich_su_on_the`
